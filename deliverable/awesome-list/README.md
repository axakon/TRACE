## Contribution

### What goes here

- Pointers to third-party resources, organized by category (skills, MCP servers, rules).
- A short note per entry explaining what it does, why it's worth knowing about, and any caveats.
- Links to the source repository, marketplace listing, or canonical documentation.

### What does NOT go here

- Skills, MCP servers, or rules authored by the TRACE project itself → those live in [`../plugin/`](../plugin/).
- Long-form rationale for why a resource is recommended → keep entries terse here; if the argument is substantial, write a reference doc in [`../../docs/reference/`](../../docs/reference/) and link to it.
- Forks or copies of upstream resources — only links. Adopters fetch directly from the source.

### Curation criteria

A candidate enters the list when:

- It addresses a workflow or capability the playbook recommends.
- It is maintained — recent commits, responsive to issues.
- It is portable — usable without adopting an entire ecosystem.
- It is opinionated in a way that aligns with the playbook (or where it diverges, the divergence is explicit and worth knowing about).

Entries are removed when they stop meeting these criteria (abandoned, broken, or superseded). Removal is a deliberate act, not a cleanup pass.
